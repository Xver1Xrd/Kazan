# `/api/photos` — загрузка фото на сервер

Одна функция обслуживает галерею:

| Метод | Что делает | Ответ |
| --- | --- | --- |
| `GET /api/photos` | список сохранённых снимков, свежие первыми | `{ "photos": [{ id, url, caption, uploadedAt }] }` |
| `POST /api/photos` | принимает снимок и сохраняет его | `{ "photo": { … } }` |

Тело `POST` — JSON: `{ "data": "<base64>", "contentType": "image/jpeg", "caption": "закат над казанкой" }`.
Браузер уменьшает кадр до 2560 px по длинной стороне и пережимает в JPEG,
поэтому с телефона уходит меньше мегабайта вместо исходных 5–12 МБ.
Сервер принимает не больше 3 МБ на снимок и только картинки
(JPEG, PNG, WebP, GIF, AVIF, HEIC/HEIF).

Подпись хранится прямо в имени файла (`<id>__<подпись в base64url>.<ext>`),
поэтому отдельная база данных не нужна.

## Где лежат файлы

Хранилище выбирается по переменной окружения `BLOB_READ_WRITE_TOKEN`:

* **есть токен** — файлы уходят в [Vercel Blob](https://vercel.com/docs/vercel-blob),
  в папку `uploads/`, и отдаются с CDN. Это рабочий режим на проде: файловая
  система serverless-функции доступна только для чтения, локально сохранять некуда.
* **нет токена** — файлы пишутся в `public/uploads/` и отдаются как обычная
  статика по `/uploads/<файл>`. Так работает `npm run dev`, `npm run preview`
  и любой свой сервер с диском. Папку можно переопределить через `UPLOADS_DIR`.

## Настройка на Vercel

1. В проекте: **Storage → Create Database → Blob**, подключить к проекту.
2. Vercel сам добавит `BLOB_READ_WRITE_TOKEN` в переменные окружения — после
   этого задеплоить заново.

Без подключённого Blob загрузка на проде вернёт понятную ошибку 503, а не упадёт молча.

## Локально

`npm run dev` поднимает тот же обработчик как middleware Vite (см. `photosApi()`
в `vite.config.ts`), так что фронтенд ведёт себя одинаково в разработке и на проде.
Загруженные локально файлы лежат в `public/uploads/` и не попадают в git.
